You are a Senior .NET 10 Architect helping implement a feature in a production-grade ASP.NET Core API called **ClinicHub**.

## Project Architecture

**Clean Architecture** with 5 layers:
- `ClinicHub.Domain` — Entities, Enums, Repository Interfaces, BaseEntity
- `ClinicHub.Application` — CQRS (MediatR), Commands/Queries, DTOs, AutoMapper, FluentValidation, Localization
- `ClinicHub.Persistence` — EF Core (SQL Server), DbContext (`ClinicHubContext`), Configurations, Seeders
- `ClinicHub.Infrastructure` — Repository Implementations, UnitOfWork, External Services (Pusher, Facebook, Google, Email, JWT, Attachments)
- `ClinicHub.API` — Controllers, Filters, Middleware, Routes, Program.cs

---

## Core Conventions

### Domain Layer
- All entities inherit from `BaseEntity<Guid>` (has `Id`, `CreatedAt`, `UpdatedAt`, `DeletedAt`, `IsDeleted`, `IsActive`, soft-delete support via `MarkAsDeleted()`)
- Private setters, domain methods for mutations
- No logic in constructors beyond property assignment

### Application Layer
- **CQRS via MediatR**: Commands (mutations) and Queries (reads) in `Features/{FeatureName}/Commands` and `Queries`
- **FluentValidation**: Every Command/Query has a `*CommandValidator` or `*QueryValidator`. No validation logic inside handlers.
- **AutoMapper**: Profiles live in `Features/{FeatureName}/{Feature}Profile.cs`
- **Localization**: Bilingual (Arabic/English) via JSON files at `Application/Localization/Resources/messages.ar.json` and `messages.en.json`. Keys are nested JSON, flattened as `"Section.Key"`.
  - Keys registered in `LocalizationKeys.cs` as static `KeyString` instances (e.g. `LocalizationKeys.PaymentMessages.NotFound`)
  - Usage: `JsonLocalizationProvider.GetLocalizedString(localizer[LocalizationKeys.SomeClass.SomeKey.Value])`
  - Inject: `IStringLocalizer<Messages> localizer`
- **Exceptions**: `NotFoundException`, `BadRequestException`, `UnAuthorizedException`, `ValidationException` — all handled globally by `ApiExceptionFilterAttribute`
- **ApiResponse<T>**: All API responses wrapped in `ApiResponse<TData>` with `Success`, `Data`, `Message`, `Errors`, `StatusCode`
- **Pagination**: `PagginatedResult<T>` (note double-g) with `Items`, `PageNumber`, `PageSize`, `TotalPages`, `TotalCount`

### Persistence Layer
- `ClinicHubContext` inherits `IdentityDbContext<ApplicationUser, IdentityRole<Guid>, Guid, ...>`
- Configurations via `IEntityTypeConfiguration<T>` — auto-discovered by assembly scan in `OnModelCreating`
- `SaveChangesAsync` auto-stamps `CreatedAt/UpdatedAt/DeletedAt` and sets `IsDeleted` on soft-delete
- All entities have `HasQueryFilter(x => !x.IsDeleted)` — soft delete is global
- `Version` property is `IsRowVersion()` (byte[]) for optimistic concurrency

### Infrastructure Layer
- **UnitOfWork**: `IUnitOfWork` exposes all typed repositories plus `GetRepository<T, TKey>()` for generic access
- All repositories extend `GenericRepository<T, TKey>` which implements `IGenericRepository<T, TKey>`
- Services registered in `DependencyInjection.cs` in Infrastructure
- HttpClient registered via `AddHttpClient<IService, Implementation>()`

### API Layer
- All controllers inherit `BaseApiController` (provides `Ok<T>`, `Created<T>`, `Deleted<T>`, `Accepted<T>` helpers — all wrapped in `ApiResponse<T>`)
- Route constants in `ApiRoutes.cs` static class per feature: `ApiRoutes.Base = "api/v{version:apiVersion}"`
- API versioning via URL segments: `/api/v1/...`
- Every controller has `[ApiVersion("1.0")]`
- Auth-required endpoints: `[Authorize]` at controller or action level

## What I Need You to Build

Implement **Paymob payment integration** for appointment booking in ClinicHub, following this exact sequence:

### Step 1 — Domain
Create a `Payment` entity inheriting `BaseEntity<Guid>` with:
- `AppointmentId (Guid)`, `UserId (Guid)`
- `Amount (decimal)`, `Currency (string)` default "EGP"
- `PaymobOrderId (string?)`, `PaymobTransactionId (string?)`
- `Status (PaymentStatus enum)`: `Pending=0, Paid=1, Failed=2, Refunded=3`
- `PaymentMethod (string?)`, `PaidAt (DateTime?)`
- Domain methods: `MarkAsPaid(string transactionId, string method)`, `MarkAsFailed()`, `MarkAsRefunded()`

Create `PaymentStatus` enum in `ClinicHub.Domain/Enums/PaymentStatus.cs`.

### Step 2 — Persistence
- EF Core configuration: `PaymentConfiguration.cs` in `ClinicHub.Persistence/Configuration`
- Add `DbSet<Payment> Payments` to `ClinicHubContext`
- Add unique index on `AppointmentId`
- HasOne Appointment with `DeleteBehavior.Restrict`

### Step 3 — Repository
- `IPaymentRepository : IGenericRepository<Payment, Guid>` in Domain with custom method `Task<Payment?> GetByAppointmentIdAsync(Guid appointmentId)`
- `PaymentRepository` implementation in Infrastructure

### Step 4 — UnitOfWork
- Add `IPaymentRepository PaymentRepository` to `IUnitOfWork`
- Implement in `UnitOfWork.cs`

### Step 5 — Paymob Service
- `IPaymobService` interface in `Application/Common/Interfaces` with:
  - `Task<string> CreateOrderAsync(decimal amount, string currency, CancellationToken ct)` → returns Paymob orderId
  - `Task<string> GetPaymentKeyAsync(string orderId, decimal amount, PaymentBillingData billing, CancellationToken ct)` → returns payment key
  - `Task<bool> ValidateWebhookAsync(string hmac, Dictionary<string, string> transactionData)` → HMAC validation
- `PaymobSettings` options class with: `ApiKey`, `IntegrationId`, `IframeId`, `HmacSecret`, `BaseUrl`
- `PaymobService` implementation using `HttpClient` (Paymob API v2)
- Register in Infrastructure `DependencyInjection.cs` with `AddHttpClient<IPaymobService, PaymobService>()`
- Add `"PaymobSettings": { ... }` section to `appsettings.json` (values empty/placeholder)

### Step 6 — Application Features (in `Application/Features/Payment`)
Commands and Queries:

**A) `InitiatePayment` Command**
- Input: `AppointmentId (Guid)`
- Handler: Gets appointment → gets doctor fee → creates Paymob order → gets payment key → creates `Payment` entity (status Pending) → saves → returns `{ PaymentKey, IframeUrl }`
- Validator: appointment must exist, belong to current user, status must be Pending, no existing paid payment

**B) `ConfirmPaymentWebhook` Command (no auth)**
- Input: raw webhook data from Paymob (transaction id, order id, success bool, HMAC, amount cents, etc.)
- Handler: validate HMAC → find payment by Paymob orderId → update status (Paid/Failed) → if Paid: update appointment status to Confirmed → save
- Returns: `bool`

**C) `GetPaymentStatus` Query**
- Input: `AppointmentId (Guid)`
- Handler: get payment by appointmentId → return `PaymentStatusDto`
- Validator: appointment must belong to current user

DTOs: `InitiatePaymentResponseDto` (`PaymentKey`, `IframeUrl`, `PaymentId`), `PaymentStatusDto` (`PaymentId`, `AppointmentId`, `Status`, `Amount`, `PaidAt`, `TransactionId`)

### Step 7 — Localization
Add keys to both `messages.ar.json` and `messages.en.json` under a `"Payments"` section. Register all keys in `LocalizationKeys.cs` in a `PaymentMessages` static class.

Keys needed: `NotFound`, `AlreadyPaid`, `AppointmentNotFound`, `Unauthorized`, `PaymobOrderFailed`, `PaymobKeyFailed`, `WebhookHmacInvalid`, `InitiateSuccess`, `StatusFetched`

### Step 8 — Routes
Add to `ApiRoutes.cs`:
```csharp

{
    public const string Initiate = Base + "/payments/initiate";
    public const string Webhook = Base + "/payments/webhook";
    public const string GetStatus = Base + "/payments/status/{appointmentId:guid}";

```

### Step 9 — Controller
`PaymentsController : BaseApiController` with `[ApiVersion("1.0")]`:
- `POST /payments/initiate` → `[Authorize]` → `InitiatePaymentCommand`
- `POST /payments/webhook` → `[AllowAnonymous]` → `ConfirmPaymentWebhookCommand`
- `GET /payments/status/{appointmentId}` → `[Authorize]` → `GetPaymentStatusQuery`

## Code Style Rules
1. Private setters on all entity properties
2. No validation logic inside handlers — only in validators
3. All user-facing strings via `JsonLocalizationProvider.GetLocalizedString(localizer[LocalizationKeys.X.Y.Value])`
4. Async/await everywhere with `CancellationToken` passed through
5. No static helper classes with side effects
6. Throw typed exceptions (`NotFoundException`, `BadRequestException`) — never return null from handlers
7. Follow existing naming: `*CommandHandler`, `*CommandValidator`, `*QueryHandler`, `*QueryValidator`
8. `await _unitOfWork.SaveChangesAsync()` — never call `_context.SaveChangesAsync()` directly from handlers
