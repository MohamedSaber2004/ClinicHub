1. USER ROLES (Flags Enum)
================================================================================

  UserType (Flags)
  ├── User          (1)  — Patient / end user
  ├── SuperAdmin    (2)  — System administrator
  ├── Doctor        (4)  — Medical doctor
  ├── Staff         (8)  — Clinic staff (receptionist, nurse, assistant)
  └── ClinicOwner   (16) — Clinic owner/manager (one clinic)

  Users can hold multiple roles via bitmask.
  Example: Doctor | User = 5

================================================================================
2. REGISTRATION & VERIFICATION FLOW
================================================================================

  User signs up (Patient / ClinicOwner / Doctor)
       │
       ├── Patient → no verification needed → start browsing
       │
       ├── Doctor → freelance or clinic-affiliated
       │
       └── ClinicOwner → submits verification docs
                          (ID, license, specialization, bio,
                           years of experience, document images)
                     │
                     SuperAdmin reviews
                     │
                ┌────┴────┐
                │ Approve │  Reject (with reason)
                └────┬────┘
                     │
              ClinicOwner is approved
              Can set up ONE clinic
              Free tier access — all core features work
                     │
              (optional) Go to external web portal
              → subscribe (Monthly/Yearly)
              → web portal calls API:
                POST /api/v1/subscriptions
              → subscription recorded
              → premium features unlocked

  KEY RULES:
  - 1 ClinicOwner = 1 Clinic (Clinic.ClinicAdminId)
  - Staff uses ApplicationUser.ClinicId + UserType.Staff role
  - No subscription required for core features

================================================================================
3. SUBSCRIPTION MODEL
================================================================================

  FREE TIER (default):
  ───────────────────
  - All core features work
  - Manage clinic, doctors, staff, bookings
  - No subscription required
  - No API enforcement on free tier

  SUBSCRIBED (optional upgrade):
  ───────────────────────────
  - ClinicOwner goes to external web portal
  - Selects plan (Monthly / Yearly)
  - Pays on the web portal
  - Web portal calls back to this API:
        POST /api/v1/subscriptions
        { clinicId, plan, amount, startDate, endDate, transactionId }
  - Subscription is recorded in Subscription table
  - Premium dashboard features unlocked

  API ENFORCEMENT:
  ───────────────
  - YES — API checks Subscription table for active subscription
  - Returns 403 Forbidden if no active subscription on premium endpoints
  - Free tier endpoints are not enforced

  PLANS:
  ─────
  - TBD (Monthly / Yearly to be defined later)

8. SUPPORTING INFRASTRUCTURE
================================================================================

  SUBSCRIPTION WEB PORTAL CALLBACK:
  ────────────────────────────────
  Endpoint: POST /api/v1/subscriptions
  Request: { clinicId, plan, amount, startDate, endDate, transactionId }
  Creates/updates Subscription record

  PREMIUM ENDPOINT PROTECTION:
  ───────────────────────────
  Custom attribute or middleware that:
  - Checks if endpoint requires subscription
  - Looks up active subscription in Subscription table for the clinic
  - Returns 403 if no active subscription

  AUDIT LOGGING:
  ──────────────
  - Already built in ClinicHubContext.SaveChangesAsync
  - Auto-logs changes to all entities

  GLOBAL QUERY FILTERS:
  ─────────────────────
  - All IClinicScopedEntity entities have automatic
    !IsDeleted + clinic scoping filter
  - When _currentClinicId is null (SuperAdmin), pass through all

10. DECISIONS MADE
================================================================================

  1. Subscription API enforcement
     YES — API returns 403 for premium endpoints when no active
     subscription. Free tier endpoints are not enforced.

  2. Staff scoping
     Staff uses ApplicationUser.ClinicId with UserType.Staff role.
     No separate Staff entity needed.

  3. Subscription web portal callback
     POST /api/v1/subscriptions
     Format TBD with web portal team.

  4. Subscription plans
     TBD — Monthly/Yearly, tiers to be defined later.

  5. Doctor appointment flow
     Doctor accepts → Staff can also manage (approve/reject/check-in).
     Staff can register walk-in patients (non-users) and book appointments.
