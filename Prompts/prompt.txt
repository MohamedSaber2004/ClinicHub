# Staff Dashboard — API Integration Guide

Base URL: `/api/v{version}` (current: `v1`)

All responses are wrapped in:

```json
{
  "success": true,
  "data": { ... },
  "message": "...",
  "errors": {}
}
```

All endpoints require `Authorization: Bearer {token}` header with a **Staff** user role.

---

## Pagination Architecture

**Staff backend → Doctory backend API**

```
Browser (JS)  →  StaffController (MVC)  →  StaffDashboardService (HttpClient)  →  Doctory API (real backend)
```

| Page | Pagination Type | How it works |
|------|----------------|--------------|
| **Appointments** | **Backend pagination** | JS sends `pageNumber` + `pageSize` to MVC controller → MVC forwards to Doctory API → API returns paginated result with `items`, `pageNumber`, `totalPages`, `totalCount` |
| **Queue (Index + Queue pages)** | **Frontend pagination** | JS fetches ALL queue items at once → slices into pages on the client side (10 per page) |
| **Overview (Index page)** | No pagination | Shows latest 5 queue items only |

### Backend must accept these query params for `GET /appointments`:
| Param | Type | Default |
|-------|------|---------|
| `pageNumber` | int | 1 |
| `pageSize` | int | 10 |
| `status` | string | optional |
| `date` | string (yyyy-MM-dd) | optional |
| `patientName` | string | optional |

### Backend must return this paginated shape (camelCase fields required):
```json
{
  "success": true,
  "data": {
    "items": [ ... ],
    "pageNumber": 1,
    "pageSize": 10,
    "totalPages": 3,
    "totalCount": 22,
    "hasPreviousPage": false,
    "hasNextPage": true
  }
}
```

**⚠️ Field names must be exactly as above (camelCase).** If the backend returns PascalCase (`Items`, `TotalPages`, etc.), the JS will see `undefined` and pagination will not render.

### What the frontend does with pagination data:
- `totalPages ≤ 0` → hides pagination entirely
- `totalPages === 1` → shows static "1" indicator (not clickable)
- `totalPages > 1` → shows clickable page links (`« 1 2 3 »`)

## 1. Dashboard Stats

**`GET /api/v1/staff/dashboard/stats`**

### Response `200 OK`

```json
{
  "success": true,
  "data": {
    "totalAppointments": 24,
    "checkedIn": 18,
    "waiting": 6,
    "completed": 8
  }
}
```

| Field | Meaning |
|-------|---------|
| `totalAppointments` | All appointments today |
| `checkedIn` | Confirmed / Accepted (checked-in) |
| `waiting` | Pending / Reserved (not yet checked) |
| `completed` | Completed |

## 2. Appointments List

**`GET /api/v1/staff/appointments?status=&date=&patientName=&pageNumber=1&pageSize=10`**

### Query Parameters

| Param | Type | Required | Notes |
|-------|------|----------|-------|
| `status` | `AppointmentStatus` enum int | No | `0=Pending, 1=Confirmed, 2=Cancelled, 3=Completed, 4=Reserved, 5=NoShow, 6=Accepted, 7=Rejected` |
| `date` | ISO date `yyyy-MM-dd` | No | Defaults to today |
| `patientName` | string | No | Partial match on patient or booker name |
| `pageNumber` | int | No | Default `1` |
| `pageSize` | int | No | Default `10`, max `100` |

### Response `200 OK`

```json
{
  "success": true,
  "data": {
    "items": [
      {
        "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
        "patient": {
          "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
          "name": "محمد عمر",
          "initial": "م"
        },
        "doctor": {
          "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
          "name": "د. سارة أحمد",
          "specialty": "أمراض القلب"
        },
        "specialty": "أمراض القلب",
        "date": "2026-07-26",
        "time": "09:00",
        "status": "pending",
        "statusLabel": "قيد الانتظار",
        "statusClass": "badge-warning",
        "phone": "0501112222"
      }
    ],
    "pageNumber": 1,
    "pageSize": 10,
    "totalPages": 3,
    "totalCount": 22,
    "hasPreviousPage": false,
    "hasNextPage": true
  }
}
```

### Status → Frontend Mapping

| `status` value | `statusLabel` | `statusClass` | Action Available |
|---|---|---|---|
| `"pending"` | قيد الانتظار | `badge-warning` | Approve / Reject |
| `"confirmed"` | مؤكد | `badge-success` | Check-in |
| `"cancelled"` | ملغي | `badge-danger` | — (read-only) |
| `"completed"` | منتهي | `badge-info` | — (read-only) |

### AppointmentStatus enum (for filtering)

```
Pending = 0, Confirmed = 1, Cancelled = 2, Completed = 3,
Reserved = 4, NoShow = 5, Accepted = 6, Rejected = 7
```

## 3. Approve Appointment

**`PUT /api/v1/staff/appointments/{id}/approve`**

### Path Parameter

| Param | Type | Description |
|-------|------|-------------|
| `id` | GUID | Appointment ID |

### Response `200 OK`

```json
{
  "success": true,
  "data": true,
  "message": "Appointments.Accepted"
}
```

### Errors

- `400` — Clinic context missing or not authorized or appointment not in a respondable state
- `404` — Appointment not found

## Error Response Shape

All errors return the standard envelope with `success: false`:

```json
{
  "success": false,
  "message": "Appointment not found",
  "errors": {
    "AppointmentId": ["Appointment not found"]
  },
  "statusCode": 404
}
```

Common HTTP status codes:
- `200` — Success
- `201` — Created (walk-in registration)
- `400` — Bad request (validation error or business rule violation)
- `401` — Unauthorized (missing/invalid token)
- `403` — Forbidden (wrong role / plan permission)
- `404` — Resource not found
