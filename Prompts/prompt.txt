All changes done. Here's what was fixed and why:
Root cause
The backend GetAllUsersQuery (in prompt.txt) has no ClinicId field. It was impossible to filter by clinic. The clinic filter on the Doctors page was essentially a no-op — it excluded ClinicOwner from the user type list but never actually filtered by the selected clinic.
The IsUnassigned filter was also broken because when isUnassigned=true, DoctorService excluded ClinicOwner from UserTypes. But to find "unassigned users" (users without a doctor record in DoctorRepository), we need both Doctor and ClinicOwner types — a ClinicOwner user naturally has no doctor record.
Changes made
File	Change
Services/RequestModels/GetAllDoctorsRequest.cs	Added UserTypes property
Services/Services/Implementations/DoctorService.cs	Now includes ClinicOwner unless ClinicId is set; passes ClinicId to GetAllUsersRequest; respects explicit UserTypes from role filter
Services/Services/Implementations/UserService.cs	Sends ClinicId in the API URL
Controllers/AdminController.cs	Accepts userTypes param; added ParseUserTypes() helper; passes to view
Views/Admin/Doctors.cshtml	New role filter dropdown (طبيب / مالك عيادة / موظف)
Backend limitation
The clinic filter (ClinicId) is now piped all the way to the API URL, but the Doctory backend GetAllUsersQuery still lacks a ClinicId property. You need to add public Guid? ClinicId { get; set; } to the backend GetAllUsersQuery class and use it in the handler to filter doctors by clinic. Until then, the clinic dropdown only affects which user types are queried (Doctor only vs Doctor+ClinicOwner).
