  ## 🔍 Why Specializations & Plans Are Not Loading — Diagnosis

  ### 1. ❌ Wrong API URL / Version in Frontend

  The routes require versioning in the URL. The correct URLs are:

    GET /api/v1/specializations/active
    GET /api/v1/plans

  If the frontend is calling /api/specializations/active or /api/v2/specializations/active (note: default version is v2 — see
  Program.cs line 71), it will get a 404.

  │ Fix: Make sure your frontend explicitly calls /api/v1/... (not /api/v2/... and not without a version number, since
  │ AssumeDefaultVersionWhenUnspecified = false).
  ──────
  ### 2. ❌  CORS Not Configured on the API Base URL

  The CorsPolicy in the backend allows any origin — but only if the correct domain is being hit. If the frontend is hitting the wrong
  base URL or the API server is not running, the request will fail silently.
  ──────
  ### 3. ❌ A uthorization Header Being Sent Anyway

  Some frontend HTTP clients (e.g. axios interceptors) automatically attach a Bearer token to every request. If an expired or
  malformed token is being sent, the JWT middleware may reject the request before it even reaches [AllowAnonymous].

  │ Fix: For anonymous endpoints, make sure you do not send the Authorization header (or send no token if it's empty/null).
  ──────
  ### 4. ❌ Query Parame ter IsFamous Filtering Out All Results

  The specializations endpoint has a default query parameter:

    GET /api/v1/specializations/active?IsFamous=true   ← default

  If no specializations are seeded with IsFamous = true, the list will be empty, not an error. Try calling:

    GET /api/v1/specializations/active?IsFamous=false

  to see if any come back at all.
  ──────
