# ClinicHub — Full Implementation Prompt

## Project Overview

ClinicHub is a **multi-tenant healthcare SaaS platform** built with **Clean Architecture + CQRS**. It connects patients with clinics and doctors, supporting clinic discovery, appointment booking, payment processing (Paymob), real-time chat (Pusher), social features (posts/comments/reactions), and multi-language (EN/AR).

### Technology Stack
- .NET 10 (net10.0), C# with nullable enabled, implicit usings
- EF Core + SQL Server + NetTopologySuite (spatial types)
- MediatR (CQRS), AutoMapper, FluentValidation
- ASP.NET Core Identity + JWT Bearer + Facebook/Google OAuth
- Paymob (payments), Pusher (real-time), Google Maps + Nominatim
- Serilog (Seq sink), NET-Tracker (monitoring)
- AspNetCoreRateLimit, Scalar (API docs, not Swagger)
- JSON-based IStringLocalizer (Arabic default, English fallback)

### Solution Structure
```
Domain (Entities, Enums, Repo Interfaces, BaseEntity)
  ← Application (CQRS Commands/Queries, DTOs, Profiles, Validators, Localizer, Interfaces)
    ← Persistence (DbContext, Configurations, Migrations, Seeders)
      ← Infrastructure (Repo Implementations, UnitOfWork, External Services)
        ← API (Controllers, Routes, Filters, Middleware, Program.cs)
```

DI registration order: `AddApplicationServices` → `AddPersistenceServices` → `AddInfrastructureServices`

## Coding Conventions (MANDATORY — Follow These Exactly)

### Architecture & Patterns
- **Clean Architecture**: Strict layer dependencies. Domain has ZERO dependencies.
- **CQRS with MediatR**: Commands in `Features/*/Commands/`, Queries in `Features/*/Queries/`. Handler classes named `*CommandHandler` / `*QueryHandler`.
- **Repository Pattern + Unit of Work**: `IGenericRepository<T, Guid>` base. Domain-specific repo interfaces in `Domain/Repositories/Interfaces/`. Implementations in `Infrastructure/Repositories/Implementations/`. All accessed via `IUnitOfWork`.
- **Pipeline Behaviors** (in order): `UnhandledException` → `Validation` → `Performance` (>600ms) → `Logging`
- **AutoMapper**: Profiles in each feature module's `DTOs/` folder. One `MappingProfile.cs` per feature.
- **FluentValidation**: One validator per Command/Query. Inject `IStringLocalizer<Messages>` for error messages. Use localization keys from `LocalizationKeys` static class.

### Naming & File Structure
- **PascalCase** for classes/methods, `_camelCase` for private fields
- **One file = one class = one handler**
- DTOs named `*Dto` or `*Response`/`*Request`
- Commands: `CreateXCommand`, `UpdateXCommand`, `DeleteXCommand`
- Queries: `GetXQuery`, `GetAllXQuery`
- Validators: `CreateXCommandValidator`, `UpdateXCommandValidator`

### Entity Rules
- All entities inherit from `BaseEntity` (provides `Id` Guid, soft delete, audit fields)
- **Soft delete**: Set `IsDeleted = true` in handler. DbContext intercepts `EntityState.Deleted` in SaveChangesAsync.
- Use `MarkAsCreated()`, `MarkAsUpdated()`, `MarkAsDeleted()` methods on BaseEntity.

### API Layer Rules
- All controllers inherit from `BaseApiController` (injects `IMediator`)
- Return `ApiResponse<T>` using helper methods: `Ok()`, `Created()`, `Deleted()`, `Accepted()`
- Route constants in `ClinicHub.API/Routes/ApiRoutes.cs` using nested static classes
- Controllers decorated with `[ApiVersion("1.0")]`
- Most endpoints require `[Authorize]` (exceptions: auth endpoints)
- Custom `[RoleAuthorize(UserType.SuperAdmin)]` for admin-only endpoints
- Global exception handling via `ApiExceptionFilterAttribute`
- Default culture is Arabic; set via `Accept-Language` header

### Localization
- All user-facing messages use `IStringLocalizer<Messages>`
- Keys defined in `LocalizationKeys` static class (grouped by module)
- JSON resource files: `messages.ar.json` (default), `messages.en.json`
- Access in validators via `localizer["KeyName"]`

## 12-Phase Implementation Workflow

### Phase 1: Research & Planning
1. Analyze requirements, entity fields, and relationships
2. **WAIT for user approval** before proceeding to code

### Phase 2: Domain & Persistence
3. Create/modify entity in `Domain/Entities/` (inherit `BaseEntity`)
4. Create repo interface in `Domain/Repositories/Interfaces/` (inherit `IGenericRepository<T, Guid>`)
5. Create EF config in `Persistence/Configuration/` + register in `ClinicHubContext`
6. Create migration

### Phase 3: Infrastructure
7. Implement repo in `Infrastructure/Repositories/Implementations/`
8. Add to `IUnitOfWork` (interface in Domain, implementation in Infrastructure)

### Phase 4: Application Logic
9. Create DTOs and AutoMapper Profile in `Application/Features/[Feature]/DTOs/`
10. Create MediatR Command/Query + Handler in `Application/Features/[Feature]/`
11. Create FluentValidation validator (inject `IStringLocalizer<Messages>`)

### Phase 5: Presentation
12. Add route constants to `API/Routes/ApiRoutes.cs`
13. Create/update controller in `API/Controllers/Version1/`

### Phase 6: Verification
14. Build + run project, test via `.http` files or Scalar docs
15. Verify database state
