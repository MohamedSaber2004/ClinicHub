• GetMyAppointments only returns appointments where:

  a.BookedByUserId == _currentUserService.UserId

  It does not exclude new appointments because they are Pending or Reserved; it has no date filter either. /E:/ClinicHub/
  ClinicHub.Application/Features/Appointments/Queries/GetMyAppointments/GetMyAppointmentsQueryHandler.cs:25

  The likely cause is an identity mismatch:

  - On creation, the appointment owner is always the currently authenticated caller: BookedByUserId = _currentUserService.UserId. /E:/
    ClinicHub/ClinicHub.Application/Features/Appointments/Commands/CreateAppointment/CreateAppointmentCommandHandler.cs:58

  - If a clinic owner/staff creates it through /admin/dashboard/appointments, that staff/owner becomes the booking user.
  - When the actual patient later calls /appointments/my, their user ID differs, so the query correctly returns no row.

  A newly created appointment appears in /appointments/my only when both calls use the same patient bearer token.

  Other exclusion paths:

  - If the request uses ?status=..., its value must match the new status: Pending for free clinics, Reserved for clinics with a
    consultation fee. /E:/ClinicHub/ClinicHub.Application/Features/Appointments/Queries/GetMyAppointments/
    GetMyAppointmentsQueryHandler.cs:32

  - The EF global clinic filter can hide appointments if the token has a different ClinicId claim. /E:/ClinicHub/ClinicHub.Persistence/
    ClinicHubContext.cs:81

  - /appointments and /appointments/my currently have no explicit authorization attribute, while /reservations does. The endpoints
    should require authentication because both depend on the current user. /E:/ClinicHub/ClinicHub.API/Controllers/Version1/
    AppointmentsController.cs:42

  So the main design issue is: dashboard-created appointments have no way to specify the patient who owns the booking. If that is your
  intended workflow, add a patient user ID to the dashboard creation command and use it for BookedByUserId; keep the public reservation
  endpoint restricted to the authenticated patient.
